# Implementation status

[Deutsch](AUSBAUSTAND.md) · **English** · [← README](../README.en.md)

As of 26 October 2026 · Version 0.22.0. Earlier dated verification reports below describe their respective historical state. See [VALIDATION.en.md](../VALIDATION.en.md) for the current verification scope and remaining limitations.

Since 0.22.0, Word export presents two goals: “Preserve appearance as closely as possible” and “Edit text and tables”. Text-only output and server selection are under “Other options”. Preflight groups notices by text location. Font comparison accounts for rotated geometry, Unicode tracking and horizontal scaling. Visible previews precede queued neighbours; additional OCR preparation pauses during input. Caret following accounts for horizontal scrolling and mobile viewport movement.

- Export verification has bounded waits, remains cancellable and restarts the complete check at most once after a timeout. Unverified output stays blocked; the edit remains open for another attempt.

- Compression preserves text, vectors, links and form fields by default, selectively reducing compatible RGB JPEGs. Lossless optimization and an explicit page-image mode are also available. The comparison uses shared zoom and synchronized scrolling. Document-level structures require one complete PDF; signed documents are rejected.
- OCR handles mixed pages. “Apply corrections” writes edited lines into the PDF search layer without changing visible pixels or native text. Existing search text is removed before replacement. Small scan skew is retained in text geometry and font matching.
- The additional local Word mode creates flowing paragraphs, supported grid tables, images and repeating headers/footers. Complex graphics may remain images; pagination, reading order and unrecognized tables require review. Single-row and single-column tables are supported by the PDF editor too.
- Recovery and project files include zoom, scrolling and typed drafts for specialist tools, including table corrections, OCR review, form mail merge, measurement, conversion settings and workflows. Passwords, file-picker handles and review confirmations are excluded. Output files remain in the separate results tray.
- Linear and graph batches save an atomic local checkpoint after each completed step. Reopen the same files and workflow to resume. Completed files can be downloaded individually or as a partial ZIP; failed files can be retried. Web Locks exclude concurrent runs of the same batch. The 160 MB batch store includes controls to remove older batches.
- Previews release decoded page resources after rendering; OCR output does not add an editor-cache copy. Fictional regressions inspect actual PDF, DOCX and batch output. Physical mobile tests remain pending: [device checklist](quality/editor-device-checklist.md).

Automatic scan matching checks 56 faces across 14 families and up to three nearby original samples. Short numbers require multiple agreeing references; suitable right-angle crops are supported. Mixed styles and arbitrary angles remain limited. Export review separates output verification from original-font similarity and provides automatic detail pairs with shared zoom. [Physical-device checks](quality/editor-device-checklist.md) are documented separately and remain pending.

“Edit PDF” displays pages immediately and automatically prepares existing text and scans. OCR runs locally, one page at a time; German and English are selected by default. Rotated lines, existing OCR layers and larger image regions on mixed pages are considered. Low-confidence words are marked. Export retains recognised search text outside removed text runs; adding OCR alone does not change the page image. Rebuilt pages may lose vectors, links and forms. Limits remain 80 MB and 200 pages; dynamic XFA forms must first be saved as regular PDFs.

Individual text runs can be edited directly on the PDF with a text cursor and font toolbar; paragraph selection is optional and must be checked for columns and tables. Digital text detection retains original font, point size, bold/italic, colour and character spacing. Reusable embedded fonts are retained; missing characters trigger explicitly reported substitution. 14 local families provide 56 faces, including Liberation, Carlito and Caladea. Text edits retain unchanged vectors when targeted original object editing and independent text verification succeed. Otherwise export stops until an image rebuild is explicitly enabled. Pure scans may be rebuilt automatically with an export notice. Native text editing preserves images, table rules and links. Supported static Type 1/CFF1 fonts are locally normalised to TrueType outlines; missing characters receive individual fallback fonts. Suitable slanted text retains its baseline. Mirrored, sheared, vertical or clipped text remains restricted. Overflow and collisions with other text block export. Selection alone does not count as an edit. Scans do not provide a reliably recoverable original font; their font and size remain estimates. Alongside text-box wrapping, an explicit preview can continue one unobstructed paragraph column onto up to 20 new pages. Tables, images, forms and complex document-wide Word-style flow remain excluded.

“New document”, beside “Projects”, opens a local document editor with rich text,
images, tables, page settings, headers, footers and page numbers. Drafts are saved
in this browser and can be transferred as editable .moindoc files. The responsive
writing view and actual PDF page preview are separate; PDF exports contain selectable
text. Creation and draft import also work on local HTTP installations.

Tool navigation restores the previous category, search, scroll and focus. Duplicate
uploads are detected by their contents. Results show format, size and known page
counts, allow filename editing and support native file sharing when available.

The entire language catalogue, originally 4,513 entries, has been reviewed. Around 2,000 translations were improved; missing UI messages and app-owned text in reports and document outputs were added. Regression tests check original data, form values, embedded invoices and language coverage.

The interface offers up to six sortable favourites, recently used tools, a document overview and a mobile action bar in the shared PDF workspace. The changing sailor illustration remains visible on mobile devices and is hidden in the desktop layout from 1101 pixels. Desktop global tool search has its own row below the top bar. Tool cards and icons remain still. The project button uses a subtle white/green design. Working states without pages also offer undo and redo. The tool sidebar starts collapsed. The header and upload area retain their existing layout and colours; compression offers Gentle, Balanced and As small as possible. The handbook is available in German and English. Sample PDFs are generated in the selected app language. Evidence for technical features is recorded in the corresponding verification runs; a version number does not replace a functional check.

## New in 0.21.0

Shared PDF export verification checks readability and known page counts. With source-page mapping it compares dimensions, links and form fields; tools that preserve text also check original text. Verification covers up to 200 pages and 100,000 characters per page. Findings require explicit review; unreadable results cannot be downloaded. Encrypted PDF output is labelled as not content-verified. This is not a complete visual comparison.

Project snapshots and archives support optional password encryption with a minimum of twelve characters. Export review lists included source files and earlier edits. Flattened handoff exports visible page images up to 2800 pixels without source files, attachments or project history. Searchable text, links, interactive forms and certificate signatures are not retained. Visible confidential information remains visible. Browser storage is still unencrypted.

Projects includes storage usage, an explicit persistent-storage request and offline packages. Offline use requires HTTPS or localhost, a supported browser and a completed download of the app and selected languages/runtimes. Every program file is integrity-checked. Updates activate once all older app tabs close. Server tools still need the user's document server. Removing offline files does not delete projects or results.

Unfinished offscreen previews are cancelled immediately so newly visible pages do not have to wait. Completed preview images are released after a short retention period. OCR allows at most two main workers on devices reporting at least 8 GB memory and eight logical cores, otherwise one. Language probes can use a separate short-lived worker. Input size and active page limits are not raised without additional load-test evidence.

Physical iPhone/iPad/Android/Windows touch devices and native Microsoft Word roundtrips remain separately pending; browser automation is not evidence of those checks. See the [device checklist](quality/editor-device-checklist.md).


## Verification and release

59 engine and interface test suites check processing, navigation and display settings. PDF outputs are read back independently, covering text, glyphs, image pixels, links, forms, font sizes, page order, project archives, real HEIC/PSD decoding and actual OCR with the shipped language models. Dense two-column pages are ordered without quadratic full comparisons and checked for complete text preservation.

Server checks cover real LibreOffice inputs, SVG/vectors, editable slides, translation overflow, veraPDF and synthetic CA/TSA/CRL evidence for long-term signatures. Passing a synthetic test does not replace production configuration of the timestamp service.

Release requires type checking, formatting checks, linting, a production build and complete Docker CI. Browser checks cover every tool view on desktop and narrow touch viewports, downloads, mixed paragraph formatting, new continuation pages, project transfer, eight OCR languages and real local model inference. Every new source commit receives its own verification run. Incomplete or failed checks are not replaced by older successful runs.

## XFA and print-standard review (11 October 2026)

PDF.js 6.3.289, examined on 11 October, can display pure dynamic XFA forms and write simple inputs back into dataset packets through `annotationStorage`. This is not a complete XFA runtime: saving explicitly does not support XFA as a single stream; hybrid forms, JavaScript, calculations and dynamic actions are not fully covered. Version 0.11.0 added this limited data editor with rejection of unsupported forms and independent read-back checks. Existing guards remain active to prevent loss of XFA data.

MoinPDF now uses PDF.js 6.4.299. The XFA guards were checked again with this version; full XFA editing remains unreleased. The following source analysis refers to the version originally examined: [document detection](https://github.com/mozilla/pdf.js/blob/v6.3.289/src/core/document.js), [saving](https://github.com/mozilla/pdf.js/blob/v6.3.289/src/core/worker.js), [input layer](https://github.com/mozilla/pdf.js/blob/v6.3.289/src/display/xfa_layer.js).

A CMYK profile alone does not establish PDF/X compliance. veraPDF supports [PDF/A and PDF/UA](https://docs.verapdf.org/validation/), not a complete PDF/X validation profile. The examined free validator [pdf0](https://github.com/mgilbir/pdf0/blob/main/docs/validators.md) also describes its PDF/X checks as limited. Releasing validated PDF/X output still requires a complete independent validator. The [CGATS21_CRPC6 ICC profile](https://registry.color.org/profile-registry/CGATS21_CRPC6), which may be redistributed unchanged, could be used for the corresponding printing condition, but replaces neither colour management nor compliance validation. No unverified PDF/X export was added.

The paragraph editor also stores logical text as PDF ActualText. Readers without ActualText support may determine a different copy order for unusual mixed-direction text, such as a right-to-left paragraph containing mostly Latin text. Rendering and re-editing use the complete stored paragraph.

## Website link to PDF

## PDF editor extension 0.16.0

Selected words can use different formatting within one text box. Selection survives formatting; insertion and replacement retain the affected style. Without a selection, formatting applies to the entire text box. Custom static TrueType fonts are checked locally and retained in project files without duplicating their bytes in each undo step. A font file contains one face; another bold/italic face requires a matching file or a bundled family.

Layout proposals leave other text boxes in place. PDF tables and columns often lack semantic structure, so paragraph grouping remains conservative. OCR corrections can be checked against the original crop and the selected area can be recognised again. Suggestions only replace text after acceptance.

Export reopens the generated PDF and checks character counts and edited-text positions, normalising whitespace and Unicode compatibility forms. Visual comparison checks outside the edited rectangles at 900-pixel preview resolution with a raster tolerance. It may miss small differences and does not verify typography inside edited areas. Cropped or additionally raster-edited pages are labelled as partially checked. The original and export remain available for manual comparison.

Verification: 46 local test suites, production build, typecheck and lint, including word formatting, Unicode, project/font round trips and missing/duplicated export text. Browser results are retained as artifacts in the editor CI. No claim for arbitrary customer PDFs, handwriting or physical mobile devices. Complex shaping, custom variable/CFF fonts and document-wide Word reflow remain technical limits.

## Editing precision in 0.17.0

Mixed formatting is explicit; font status and controls follow the selected text range. Without a text selection, formatting still applies to the whole text box. Built-in find/replace (Ctrl/⌘+F or +H within the text box) deliberately searches only that box. Each match retains its own style and replacements share one undo step. Queries are literal; the 20,000-character text-box limit remains.

The actual editor page zooms up to 400 percent while controls retain their size. The page has a separate scrolling area. Screen previews are bounded to a 3,200-pixel longest side and existing renderer limits; this does not describe export resolution. Full Acrobat equivalence or a best-internet-tool ranking has not been demonstrated. An independent comparative corpus and physical-device testing are still needed for such an assessment.

## Text blocks, export verification and public corpus in 0.18.0

Untouched pages are copied directly on export. Opening, searching or re-recognizing a scan alone neither adds a text layer nor replaces an existing one. OCR text is applied only when that page is actually edited.

Explicitly join 2–50 horizontal fields on the same page or split at the cursor. Preview reading order before applying. Source removal rectangles stay separate; grouping alone does not rewrite the PDF. Splitting is an explicit layout change and only its first half owns the original removals. Different custom font files or scan backgrounds are not silently unified.

Whole-document search includes current edits, reports skipped pages and optionally runs local OCR. Limits: five million indexed characters, 5,000 matches, 20,000 characters per field. Font, overflow and collision checks run before a batch replacement; one failing match retains the entire previous state. Content changes invalidate stale results. Undo reverts the whole replacement together.

Inside edited fields, the export check renders intended glyph outlines directly to Canvas and compares them with the reopened PDF.js rendering at 1,600 pixels along the longest side. A one-pixel positional tolerance accommodates raster differences. Signed ink coverage is compared per RGB channel, so antialiased edges do not count like fully missing text pixels. More than twelve percent missing or additional coverage yields a review notice; tiny/low-contrast text or failed background separation is marked incompletely checked. This is not an equality proof or an OCR correctness check. The unchanged-area comparison remains at 900 pixels.

Regressions cover interleaved columns, tables, styled joining/splitting, Unicode boundaries, search invalidation and deliberately incorrect font, size, colour and position. `tests/editor-quality-browser.py` adds desktop and 390-pixel Chromium, Firefox and WebKit flows. Actual CI results, exported PDFs, reports and screenshots are retained in `editor-*` artifacts.

Run `python tests/editor-download-corpus.py` for immutable public samples. Sources, revisions, SHA-256 hashes, licences and caveats are in `tests/editor-public-corpus.json`. AWS's sample already contains text mapping errors; preserve that baseline outside edited anchors. The mixed file is assembled for testing. A minimal AcroForm checks explicit refusal before destructive flattening, not arbitrary government-form editing. These PDFs are not deployed with the app, and no document upload has been added.

Physical iPhone/Android devices, full native Safari editor interaction and a broad production-customer corpus remain unverified. Camera captures, handwriting, complex shaping, arbitrary signatures and forms remain technical limits.

## 0.19.0 – 20 October 2026

- Eligible horizontal word edits remove only affected original characters. Unchanged prefixes, and suffixes whose positions still agree, retain native PDF text. Ambiguous mappings, ligatures, style or layout changes continue to use verified whole-field editing.
- Link text fields in a chosen order across existing pages. Preview text and style distribution without automatic shrinking; overflow and collisions prevent application. Preview the flow again after further edits.
- Simple aligned tables gain cell editing with Tab/Shift+Tab. A format painter, millimetre measurements and edge, centre and baseline guides support precise editing.
- Document-wide change list with before/after text, navigation and independent reversion. Related splits and text flows revert together while unrelated later edits remain.
- Move, proportionally resize, replace and crop individual original images in the text editor. Cropping removes image pixels while retaining orientation. Scan backgrounds, groups and images with existing associated OCR layers are handled conservatively; image decoding and cropping are limited to 4 megapixels.
- Local OCR working copies support small-angle deskew, shadow compensation, contrast and conservative noise reduction. Compare original and processed region recognition; suspicious letters in numbers are flagged for review. No automatic numeric correction or new document transmission.
- Unambiguous full-page scans up to 4 megapixels retain their original pixel grid. An independent PDF.js rendering must confirm decoded image data; annotations, layers, extra objects or mismatched image geometry prevent this path. Complex scan pages continue to use the raster rebuild.
- Touch mode adds larger handles, a compact expandable font toolbar, a selection magnifier and caret adjustment for the visible keyboard area. Physical devices and native virtual keyboards require separate verification.
- Font appearance checks adapt resolution to text size up to a 3,600-pixel long edge, bounded to approximately 4 megapixels, and highlight mismatch locations. The pinned public corpus adds a French accent scan, with checksums and licence attribution; test documents are not shipped with the application.

PDF object character order may change during replacement. Geometrically sorted text extraction is checked; semantic reading order and complete preservation of existing accessibility tags are not thereby proven.
